Here's my recommendation: Option 1 — Purchase exit does NOT set cooldown.

Reasoning:

  1. The whole point of Flow 2 is to upsell remaining reviews after payment. If purchase-exit sets a cooldown, Flow 2 would almost never fire (most invoices are paid within 14 days of order creation).
  2. The cooldown's purpose is to prevent email fatigue — don't bombard a customer with multiple email sequences. A purchase isn't an email sequence, it's an exit event.
  3. Flow 2 itself will set the cooldown once it triggers, which correctly prevents other flows from firing for the next 14 days after the customer starts receiving Flow 2 emails.
  4. The abandoned cart flow already gets stopped by the tag cleanup on order creation — no cooldown needed to prevent it.

So the logic would be:

  1. Order created → exit all flows (add "purchased" tag, remove all active tags), but no cooldown set
  2. Flow triggers (abandoned cart, Flow 1, Flow 2) → set 14-day global cooldown

This means: customer orders → exits flows → pays invoice 5 days later → Flow 2 checks eligibility → triggers if remaining reviews exist → sets cooldown

This keeps the system clean and ensures Flow 2 actually works as intended.
